A select is a field that picks one value from a list. Press it and a white panel drops under it holding a row per option, drawn the way a [Menu](/docs/components/menu) panel is. On a touch device the platform's picker opens in its place. Options come from the `options` prop.

A select usually sits on a `glass` [Card](/docs/components/card) or on the page background. Almost never on a white default card. The exception is a white card nested inside another card.

Anything that looks like a select is held to the same rules, whether or not it is one. A hand-written `<select>` in site chrome, or a button that opens a menu and is drawn as a field, takes the select's height, radius, padding, edge, chevron, and focus ring at the size it matches. Reach for the component first. Where it can't be the component, copy the select at one of its [sizes](#size) rather than approximating it.

How a field goes together with its label, its description, and its messages is on the [Forms](/docs/patterns/forms) page.

## Examples

### Label and description

`label` is what the select is for, and every select in a form column gets one. `description` is a second line under it, for what the label can't hold. Both render above the control, and the label is wired to the control with `for`.

<Card surface="glass">
  <div class="not-prose">
    <Select
      client:load
      label="Time zone"
      description="Scheduled messages go out in this zone."
      options={[
        { value: 'america/new_york', label: 'Eastern Time' },
        { value: 'america/chicago', label: 'Central Time' },
      ]}
    />
  </div>
</Card>

Leaving `label` off is how a [compact field](/docs/patterns/forms#compact-fields) is written, and that's the only place it's right.

### Required

`required` marks the select with a rose `2xs` [Badge](/docs/components/badge) to the right of the label and marks the control required. Pass `required="label"` on the first required field in a form, which spells out **Required**. Pass `required` on the rest, which shows the asterisk alone with a tooltip. The [Forms](/docs/patterns/forms#required) page has the rule.

<Card surface="glass">
  <div class="not-prose flex flex-wrap gap-4">
    <Select client:load label="Country" required="label" options={[{ value: 'us', label: 'United States' }, { value: 'ca', label: 'Canada' }]} />
    <Select client:load label="Time zone" required options={[{ value: 'america/new_york', label: 'Eastern Time' }, { value: 'america/chicago', label: 'Central Time' }]} />
  </div>
</Card>

### Options

The `options` prop takes an array of `{ value, label }`. An option can also carry `disabled`, which fades its row to half and keeps it from being chosen.

<Card surface="glass">
  <div class="not-prose">
    <Select
      client:load
      options={[
        { value: 'america/new_york', label: 'Eastern Time' },
        { value: 'america/chicago', label: 'Central Time' },
        { value: 'america/denver', label: 'Mountain Time' },
        { value: 'america/los_angeles', label: 'Pacific Time' },
        { value: 'america/anchorage', label: 'Alaska Time', disabled: true },
      ]}
    />
  </div>
</Card>

An entry with a `label` and `options` of its own is a group. Its label heads its options in the list and can't be chosen. A first option with an empty value stands in for no choice at all.

<Card surface="glass">
  <div class="not-prose">
    <Select
      client:load
      options={[
        { value: '', label: 'All campaigns' },
        {
          label: 'Running',
          options: [
            { value: 'spring-promo', label: 'Spring promo' },
            { value: 'welcome', label: 'Welcome series' },
          ],
        },
        { label: 'Finished', options: [{ value: 'black-friday', label: 'Black Friday' }] },
      ]}
    />
  </div>
</Card>

The value is bound with `v-model`. A select with no value rests on its first option and sets `v-model` to match, the way a native `<select>` does. Anything else you pass, such as `aria-label`, lands on the control rather than the wrapper around it. An `id` of your own lands there too, and the label points at it.

```html
<Select v-model="timeZone" :options="timeZones" name="time_zone" />
```

`name` is the exception. It lands on a native `<select>` hidden inside the control, which holds the same value and submits it with the form. That `<select>` fires `change` when the choice changes, and takes `required` so the browser holds back a form with nothing chosen.

### Placeholder

`placeholder` is what the control shows while no option matches the value, under the same [rule for placeholders](/docs/patterns/forms#placeholders) as any other field. A select with a placeholder and no value stays empty rather than resting on its first option.

<Card surface="glass">
  <div class="not-prose">
    <Select
      client:load
      placeholder="Select a segment"
      options={[
        { value: 'vip', label: 'VIP customers' },
        { value: 'lapsed', label: 'Lapsed 90 days' },
      ]}
    />
  </div>
</Card>

### Surface

A select works out what it is sitting on for itself, by asking the [Card](/docs/components/card) or [Navbar](/docs/components/navbar) it's inside. The white fill holds on every surface. What draws the boundary is what changes.

| Sitting on   | Which is     | Boundary          |
| ------------ | ------------ | ----------------- |
| `default`    | white        | slate-200 border  |
| `glass`      | slate-50     | slate-200 border  |
| `sunken`     | slate-300/30 | shadow, no border |
| `dark`       | slate-700    | shadow, no border |
| `background` | slate-200    | shadow, no border |

White and glass get the border. Sunken, dark, and the page background get the shadow and no border. Glass is a step off white, close enough that a border still reads as the edge. From sunken down the shadow does that job, and a border would only double it.

<SelectSurfacesExample client:load />

The page background is the one surface with no component to announce it. That's what `sitsOn` is for. An element that paints a background of its own can wrap its contents in [SurfaceProvider](/docs/components/card#a-surface-that-isnt-a-card) instead.

The list is the same on every surface. It is white with a slate-200 border and a large shadow.

### Size

The `size` prop sets height, padding, and text size. The sizes are `xs`, `sm`, `md` (the default), `lg`, and `xl`. They match [Button](/docs/components/button) at every step, so a select and a button in the same row are the same height and share a corner radius.

<Card surface="glass">
  <div class="not-prose flex flex-wrap items-center gap-3">
    <Select client:load size="xs" options={[{ value: 'xs', label: 'xs' }]} />
    <Select client:load size="sm" options={[{ value: 'sm', label: 'sm' }]} />
    <Select client:load size="md" options={[{ value: 'md', label: 'md' }]} />
    <Select client:load size="lg" options={[{ value: 'lg', label: 'lg' }]} />
    <Select client:load size="xl" options={[{ value: 'xl', label: 'xl' }]} />
  </div>
</Card>

Text runs `text-xs` at `xs` and `sm`, `text-sm` at `md` and `lg`, and `text-base` at `xl`. The list takes the control's corners, and its rows are the same at every size.

### Width

A select is as wide as its longest option. Add `block` to fill the container instead, which is what a select in a form column wants. The list is at least as wide as the control.

<Card surface="glass">
  <div class="not-prose space-y-3">
    <Select
      client:load
      options={[
        { value: 'all', label: 'Sized to its options' },
      ]}
    />
    <Select
      client:load
      block
      options={[
        { value: 'all', label: 'block' },
      ]}
    />
  </div>
</Card>

### Error and hint

`error` takes the message to show under the control. Passing it recolors the border, the text, and the chevron, marks the line with a warning icon, and points `aria-describedby` at the message.

<Card surface="glass">
  <div class="not-prose">
    <Select
      client:load
      error="Pick a time zone before saving"
      options={[
        { value: '', label: 'Select a time zone' },
        { value: 'america/new_york', label: 'Eastern Time' },
      ]}
    />
  </div>
</Card>

The border is there in the resting state too, so only its color changes and nothing moves when a form fails validation. On the page background the resting border is transparent rather than absent, for the same reason.

`hint` is the same line before anything goes wrong, at slate-600 behind an info mark. A select can show both.

<Card surface="glass">
  <div class="not-prose">
    <Select
      client:load
      label="Sending number"
      hint="Only numbers assigned to this group are listed."
      options={[{ value: '1', label: '(555) 019-2841' }]}
    />
  </div>
</Card>

### Disabled

`disabled` swaps the white fill for slate-100 with slate-500 text and stops the control from opening its list. On a shadowed surface the shadow goes and a slate-200 border takes over, so the control still has an edge.

<Card surface="glass">
  <div class="not-prose">
    <Select
      client:load
      disabled
      options={[{ value: 'locked', label: 'Managed by your admin' }]}
    />
  </div>
</Card>

## Interaction

On a shadowed surface, hover deepens the shadow from `shadow` to `shadow-md`. On white and glass there is no shadow, so hover does nothing. There is no press state either, because the press opens the list and the list is what gives the feedback.

Focus draws a blue outline, two pixels wide at a two pixel offset, and only for keyboard focus. Clicking the control doesn't ring it.

The list opens on a press and closes on a second press of the control, on a press anywhere outside, on <kbd>Esc</kbd>, or on an option being chosen. It sits `8px` under the control and is drawn like a [Menu](/docs/components/menu) panel, with the same border, shadow, and rows. The chosen option carries a check at the end of its row.

The list renders at the end of `<body>`, so an ancestor that clips its overflow can't clip it. It stops `16px` short of the window edge and scrolls from there. A list that doesn't fit under the control opens above it when there's more room there.

The keys are the ones a native `<select>` answers to, and focus stays on the control the whole time. <kbd>Space</kbd>, <kbd>Enter</kbd>, or an arrow key opens the list on the chosen option. The arrow keys move through the options and pass over a disabled one. <kbd>Home</kbd> and <kbd>End</kbd> go to the first and the last. <kbd>Enter</kbd> or <kbd>Space</kbd> chooses the active option, and so does <kbd>Tab</kbd> on its way to the next field. <kbd>Esc</kbd> closes the list and leaves the value alone. Typing jumps to an option that starts with what was typed.

The active option is filled slate-50, the fill a Menu row takes on hover. When a key moved it there it also takes a blue ring, drawn inside the row.

On a touch device a press opens the platform's picker in place of the list. The control looks the same, and a group's label heads its options in the picker too. Touch here means the main pointer is a finger (`pointer: coarse`), so a laptop with a touchscreen and a mouse keeps the list.

## Contrast

| Element              | On         | WCAG 2.x |
| -------------------- | ---------- | -------- |
| slate-900            | white      | 17.8:1   |
| slate-800            | glass      | 14.0:1   |
| slate-500            | glass      | 4.6:1    |
| rose-600             | white      | 4.5:1    |
| rose-800             | glass      | 7.6:1    |
| slate-500            | white      | 4.8:1    |
| slate-200            | white      | 1.2:1    |
| slate-300            | white      | 1.5:1    |
| rose-300             | white      | 1.9:1    |
| white fill           | glass      | 1.05:1   |
| white fill           | background | 1.23:1   |
| placeholder          | white      | 3.4:1    |
| black option         | white      | 21:1     |
| black option, active | slate-50   | 20.1:1   |
| disabled option      | white      | 3.9:1    |

The option text and the error message clear AA comfortably. The label is slate-800 and clears it by a wide margin. The chevron sits at slate-500, which clears AA at 4.8:1, and it is decorative in any case. The description is slate-500 too, which holds on white and glass and falls to 3.9:1 on the page background.

The boundary doesn't. The border runs 1.2:1 against the white fill, well short of the 3:1 WCAG asks of a control's boundary. The fill itself is only 1.05:1 against a glass card. On the page background the fill separates a little better at 1.23:1, with the shadow to help. The error state has the same problem, at 1.9:1 for the rose-300 border, which is why the message under the control carries the meaning rather than the color.

The placeholder is the value color at half strength, the same as an [Input](/docs/components/input)'s. It runs 3.4:1 on white, which is under AA.

The rows of the list are a [Menu](/docs/components/menu#contrast)'s rows and clear AA the same way. A group label is slate-500 on white, at 4.8:1. A disabled option runs at 3.9:1, which is under AA for text. Disabled controls are exempt, and the row can't be chosen either way.
