An action bar is the floating panel that holds the buttons that confirm or cancel the content above it. It stays 32px above the bottom of the window while the content scrolls under it, so the buttons are in reach at any point on the page.

Use it for content where a confirm or a cancel is expected, and a [Modal](/docs/components/modal) would cover context that has to stay in view. A form is one case. Sub views in the workflow builder and grid configurations are others. In analytics, dragging over a scatter plot makes a selection, and the bar holds what can be done with it.

Write it last, in the same column as the cards it follows.

```vue
<PageLayout layout="create" title="New Contact">
  <Card surface="glass" class="w-full md:max-w-2xl">…</Card>
  <Card surface="glass" class="w-full md:max-w-2xl">…</Card>

  <ActionBar class="md:max-w-2xl">
    <Button size="lg">Cancel</Button>
    <Button size="lg" color="sky" block>Save Contact</Button>
  </ActionBar>
</PageLayout>
```

It takes no props. The default slot holds the buttons.

## Examples

### Sticking

While the end of the content is below the window, the bar floats 32px above the window's bottom edge and the cards slide under it. Once the end of the content scrolls into view, the bar rests in place under the last card. Scroll the box to see both.

</div>

The bar only travels inside its parent. Put it straight in the column that holds the cards, as the last child. Wrapped in an element of its own, it has no room to travel and stays where it was written.

It sticks to the nearest ancestor that scrolls, which is normally the window. An ancestor with `overflow-hidden` counts as that ancestor even though it never scrolls, so a bar inside one stops floating.

### Surface

The panel is the `glassRaised` surface from [Card](/docs/components/card#surface), padded by 16px, then 24px from `sm`. It announces `glass` to everything inside it, so a slate [Button](/docs/components/button#surface) comes out slate-200 without being passed `sitsOn`. Like every glass raised panel, it goes on the page background only, never inside another panel.

### Buttons

The slot is a row with an 8px gap. The buttons in it follow the [two buttons](/docs/components/button#two-buttons) rule. The primary action is written last with `block` and fills the row. The secondary button sits on the left at its own width.

### Width

The bar fills the width of its parent. Give it the width class of the cards above it, so its edges line up with theirs. On a [create page](/docs/patterns/page-structure#create-pages), and for the small cards on a [sidebar page](/docs/patterns/page-structure#sidebar-pages), that is `md:max-w-2xl`.

### Resting place

At the end of the page the bar rests under the last card. [Page Layout](/docs/components/page-layout#bottom-space) leaves 24px below it, and 128px from `md`, so it settles above the bottom of the window instead of against it.

## Migration

This component replaces `vx-sticky-footer` from `@voxie/frontend-components`. The name is new. It still takes no props, and the default slot carries over. The panel is now the `glassRaised` surface, so it is `bg-white/80` with `backdrop-blur-lg` where the old one was `bg-white/70` with `backdrop-blur-md`.
