A message token represents a value that is filled in when the message is sent, such as a contact's first name. It is drawn as a chip inside the text of a message. The icon shows which record the value comes from. The text names the field on that record.

The `path` prop is the variable as the message builder writes it, without the braces. The builder's `{{contact=>first_name}}` is `path="contact=>first_name"`. The first segment is the level, and the icon replaces it. The chip draws the remaining segments with a colon between them. `contact=>first_name` reads `first_name`, and `group=>custom_attributes=>booking_link` reads `custom_attributes:booking_link`.

```vue
<p class="text-sm leading-relaxed">
  Hi <MessageToken path="contact=>first_name" after="!" /> Thanks for asking about <MessageToken path="group=>name" after="." />
</p>
```

The token's text and icons are slightly smaller than surrounding text. The size is set in ems allowing them to scale proportionally. Surrounding text uses `leading-relaxed` so a one-line chip sits inside the line with room above and below.

### As a context choice

`context` draws a context's mark and name in place of a path. The choices are `entry`, `preferred`, and `corporate`. In a boxed [Radio](/docs/components/radio) it goes where the label would, so picking a context is picking the mark the card will carry.

### Typeface

The token is set in Google Sans Code with its `MONO` axis at 0, the proportional end. It gives the feel of code without the readability and spacing problems of a fixed-width face. At `MONO` 1 every character takes the same width. The component reads the axis from `--token-mono`.

### Level

The level sets the icon and the color. `contact`, `team`, and `group` fields sit on slate. A local attribute is a contact field with a value per context. Its path starts `contact=>local`, the icon replaces both segments, and it sits on amber with the location dot.

<Card>
  <div class="not-prose flex flex-wrap items-center gap-3 text-sm leading-relaxed">
    <MessageToken path="contact=>first_name" />
    <MessageToken path="team=>name" />
    <MessageToken path="group=>name" />
    <MessageToken path="contact=>local=>membership_status" />
  </div>
</Card>

| Level            | Icon         | Color |
| ---------------- | ------------ | ----- |
| `contact`        | Globe        | slate |
| `team`           | Screen users | slate |
| `group`          | Grid         | slate |
| `contact=>local` | Location dot | amber |

A level the component doesn't know draws as `contact`.

### Preferred

`preferred` marks a local attribute read from the contact's preferred group rather than from the current context. The token turns violet and takes the star. It has no effect on the other levels.

### Longer paths

Every segment after the level is drawn, with a colon between them. A token wider than its line wraps inside its one box. It breaks after a colon, and mid-word only when a single segment is wider than the line.

### Fallback

`fallback` adds a mark after the path, for a token that has something to do when its value is empty. `next` is the boxed right arrow, for a token followed by another variable or by text. `exit` is the exit arrow, for a token that exits the flow.

<Card>
  <div class="not-prose flex flex-wrap items-center gap-3 text-sm leading-relaxed">
    <MessageToken path="contact=>first_name" />
    <MessageToken path="contact=>first_name" fallback="next" />
    <MessageToken path="group=>custom_attributes=>booking_link" fallback="exit" />
    <MessageToken path="contact=>local=>custom_attributes=>program_interest" fallback="next" />
  </div>
</Card>

### Punctuation

`before` and `after` take the punctuation touching a token, such as the `!` after a greeting or the parentheses around a name. They share the token's block, so a line never starts or ends on a stranded mark.

<Card>
  <div class="not-prose text-sm leading-relaxed text-slate-800">Hi <MessageToken client:load path="contact=>first_name" after="!" /> Your tour <MessageToken client:load path="contact=>local=>custom_attributes=>tour_date" before="(" after=")" /> is booked.</div>
</Card>

### Description

`description` makes the token a button that opens a [Popover](/docs/components/popover) with that text. The fill steps one rung on hover, one more when pressed, and holds the hover rung while the panel is open.

<Card>
  <div class="not-prose flex flex-wrap items-center gap-3 text-sm leading-relaxed">
    <MessageToken client:load path="contact=>first_name" description="First name, a contact field shared across contexts." />
    <MessageToken client:load path="contact=>local=>custom_attributes=>program_interest" fallback="next" description={'Program interest, a local attribute read from this context. If empty: "preschool".'} />
  </div>
</Card>

### Press

`press` makes the token a button that emits `press` and opens nothing, for an editor that opens something of its own. A `description` on the same token is ignored. A pressed token keeps its focus ring, including after a mouse click. `selected` draws the same ring on a token inside the editor's selection.

  </div>
</Card>
