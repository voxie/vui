Pages are typically made up of two sections. The navbar which is flexible and fills the full browser width and the main content area witch has its max width capped.

The navbar uses the navbar component.

For the main content, we use the tailwind container class with a max width and padding. Exceptions to the max width content container would instances like the message hub or workflow builder where the user needs all the space they can get for complex or heavy work tasks.

relative shadow flex justify-between items-center px-4 sm:px-6 md:px-8 bg-slate-700 h-16 sm:h-20 app-navbar mb-6 md:mb-0
container mx-auto px-4 sm:px-6 md:px-8 

```
container mx-auto px-4 sm:px-6 md:px-8 max-w-(--breakpoint-xl)
```

Headings should always sit inside cards with their content. Page titles are the exception. They sit directly on the page background.

We use a left aligned 12 column grid for most pages. Areas like a dashboard with variable width cards containing different callouts. Gaps between items should never exceed the gap between the container and edge of the screen and should ideally be slightly smaller. This grid sits at the main content level in markup not at the body level. This allows us to drop it in when needed and manage main content padding and gaps apart from the navbar. 

```
grid grid-cols-12 gap-6 md:gap-8
```

An exception to the above rules are create pages e.g. creating a campaign, segment, or contact. Those screens follow a single column centered layout and use a tighter max width of `--breakpoint-sm`. We also show a page description on the page background, directly under the page heading. The cards here are usually glass because they contain form inputs.
