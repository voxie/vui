A page is typically two parts. The [Navbar](/docs/components/navbar) runs the full width of the window. The main content area has its max width capped.

The main content sits in Tailwind's `container`, with a max width and padding. Screens like Message Hub and the workflow builder are exceptions. They drop the max width, because the user needs all the space they can get for complex or heavy work.

```
container mx-auto px-4 sm:px-6 md:px-8 max-w-(--breakpoint-xl)
```

Headings should always sit inside cards with their content. Page titles are the exception. They sit directly on the page background.

Most pages use a left-aligned 12-column grid, in areas like a dashboard with cards of different widths holding different callouts. The gap between items never exceeds the gap between the container and the edge of the window, and is ideally a little smaller. The grid sits at the main content level in the markup, not on the body. That way it can be dropped in when a page needs it, and content padding and gaps are managed apart from the navbar.

```
grid grid-cols-12 gap-6 md:gap-8
```

Create pages are an exception, such as creating a campaign, a segment, or a contact. Those screens use a single centered column with a tighter max width of `--breakpoint-sm`. A page description sits on the page background, directly under the heading. The cards are usually `glass`, because they hold form inputs.

Another common layout is a sidebar beside the main content. Edit screens for main app functions use it, such as editing a campaign, a segment, or a contact, and so do the app's configuration settings.
