Radio

A radio is a native <input type="radio"> with a drawn dot beside its label. The input itself is there, hidden to the eye and not to the browser, so it submits with a form, answers to the arrow keys, and announces itself as a radio.

A radio never stands alone. Two or more share one v-model and one name, and the model holds the value of whichever is picked. The name is what makes them a group to the browser, and without it the arrow keys won’t move between them.

Most groups are boxed, which draws each option as a bordered row filling the width of its container. The bare radio is for a set that sits inside something else, like a table row or a dense settings list. A Radio Bar lays a set out in one line, each option a label in a shared track the height of an Input.

<Radio v-model="when" name="when-to-send" value="now" label="Send now" boxed />
<Radio v-model="when" name="when-to-send" value="later" label="Schedule for later" boxed />

How a field goes together with its label, its description, and its messages is on the Forms page.

Examples

Boxed

boxed draws the row as a bordered box that fills its container. The box rests transparent with a slate-300 border, so the surface shows through, and goes white with a sky-500 border when picked. The circle centers on the block rather than on the first line, so a description pushes it down to the middle of the row. Stack boxed rows with gap-2.

Everything else on this page applies to a boxed radio as well. Error recolors the box’s border along with the circle, disabled quiets the label, and the sizes set the padding along with the circle.

A group

Each radio carries the value it puts in the model when it’s picked. Wrap the set in a <fieldset> with a <legend>, so the question above the options is read out with each of them. Stack them with gap-2, or gap-3 when they carry descriptions.

now

Picking one unpicks the rest. Nothing in the component does that, since the browser does it for every input sharing a name.

Label and description

label is the option text, and it sits beside the dot rather than above it. description is a second line under the label, for what the label can’t hold. Use the default slot instead of label when the text needs markup.

The label is font-medium and slate-800, a step lighter than the extrabold label on an Input. A radio label is the answer rather than the question. The question is the legend above the group.

Surface

A radio works out what it is sitting on for itself, by asking the Card or Navbar it’s inside. The circle is white on white and glass. On sunken, dark, and the page background it has no fill, so the surface shows through it. Its border changes with the surface too. Picking it swaps the border for a sky-500 ring and lands a sky-500 dot inside.

A radio carries no shadow on any surface, so its border runs a step darker than a Checkbox’s to hold against the surface, and the page background takes a border like the rest of them. That’s what sitsOn is for, since nothing on the page background can announce it. An element that paints a background of its own can wrap its contents in SurfaceProvider instead.

Size

The size prop sets the circle, the label, and the gap between them. The sizes are sm, md (the default), and lg, at 12, 16, and 20px. A Checkbox runs 16, 20, and 24px under the same names.

The ring is 2px at md and lg, and 1px at sm, where a 2px ring would leave the dot no gap around it.

Error and hint

error takes the message to show under the row. It recolors the border, marks the line with a warning icon, sets aria-invalid, and points aria-describedby at the message. Pass an array for more than one message.

A group has one answer, so it has one message. Put error on the last radio in the set, where the line reads as the group’s own.

hint is the same line before anything goes wrong, at slate-600 behind an info mark. A radio can show both.

Scheduled sends run in the recipient's time zone.

Disabled

disabled fills the circle slate-100 and drops the label to slate-500. A picked radio that’s disabled keeps its dot, in slate-400, rather than losing the answer along with the control.

Interaction

Nothing happens on hover. A radio has no shadow to deepen.

Pressing shrinks the circle to 90% for the length of the press, and leaves the label where it is. The shrink is motion-safe, so it doesn’t run for someone who has asked for reduced motion.

Focus draws a blue outline around the circle, two pixels wide at a two pixel offset, and only for keyboard focus. Pressing the row doesn’t ring it. A boxed radio draws the outline around the box instead, and its border steps one shade darker on hover.

Everything else is the browser’s. A group is one tab stop, landing on whichever radio is picked. The arrow keys move through the set and pick as they go, wrapping at either end.

The label, the description, and the messages clear AA.

The dot being there is what carries the answer, and a dot is a shape rather than a color, so the state survives without it. The colors themselves don’t clear. Sky-500 against a white card is 2.7:1 for the ring and for the dot, short of the 3:1 WCAG asks of a control’s boundary. The unpicked circle has the same problem at 1.5:1, and so does the rose-300 error border at 1.9:1, which is why the message under the row carries the error rather than the color.

The ring thickens when the radio is picked, at md and lg, so the weight moves as well as the color.

The disabled dot runs slate-400 on slate-100 at 2.4:1. Disabled controls are exempt from the contrast rules, and it is deliberately quiet.
