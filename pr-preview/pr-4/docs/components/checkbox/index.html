Checkbox

A checkbox is a native <input type="checkbox"> with a drawn box beside its label. The input itself is there, hidden to the eye and not to the browser, so it submits with a form, answers to Space, and announces itself as a checkbox.

The whole row is the target. The box, the label, and the description are inside one <label>, so a press anywhere in them toggles the box.

How a field goes together with its label, its description, and its messages is on the Forms page.

Examples

Label and description

label is the option text, and it sits beside the box rather than above it. description is a second line under the label, for what the label can’t hold. Use the default slot instead of label when the text needs markup.

The label is font-medium and slate-800, a step lighter than the extrabold label on an Input. A checkbox label is the answer rather than the question.

One box or several

Bind v-model to a boolean for a single box that stands on its own.

<Checkbox v-model="skipRecent" label="Skip contacts who replied" />

Bind it to an array for a set, and give each box a value. Checking one adds its value to the array, unchecking takes it out.

Notify me by
["sms"]
 
<Checkbox v-model="channels" value="sms" label="Text message" />
<Checkbox v-model="channels" value="email" label="Email" />

A set gets a <fieldset> and a <legend>, so the question above the options is read out with each of them. Stack the boxes with gap-2, or gap-3 when they carry descriptions.

Boxed

boxed draws the row as a bordered box that fills its container, the same form a Radio takes for a set of options. The box rests transparent with a slate-300 border, so the surface shows through, and goes white with a sky-500 border when checked. The marker centers on the block rather than on the first line. Stack boxed rows with gap-2.

Notify me by

Everything else on this page applies to a boxed checkbox as well. Error recolors the box’s border along with the marker, disabled quiets the label, and the sizes set the padding along with the marker. On the page background the marker inside the box drops its shadow.

Indeterminate

indeterminate draws a dash instead of a check, for a box that stands for a set where only some are on. It’s a display state. The model isn’t touched until someone presses the box, and then it’s the press you handle.

 
<Checkbox
  :model-value="all"
  :indeterminate="some"
  label="Every channel"
  @update:model-value="toggleAll"
/>

Surface

A checkbox works out what it is sitting on for itself, by asking the Card or Navbar it’s inside. An unchecked box is white on white and glass. On sunken, dark, and the page background it has no fill, so the surface shows through it. Its boundary changes with the surface too. A checked box is sky-300 with a sky-500 border on every surface.

The page background is the only surface that gets the shadow. That’s what sitsOn is for, since nothing on the page background can announce it. An element that paints a background of its own can wrap its contents in SurfaceProvider instead.

Size

The size prop sets the box, the label, and the gap between them. The sizes are sm, md (the default), and lg. The box is the line-height of its own label at every size, so the two line up on the first line however far the text wraps.

There is no xs or xl. Input, Select, and Button run the full five, and a checkbox stops at the three that stay big enough to hit.

Error and hint

error takes the message to show under the row. It recolors the border, marks the line with a warning icon, sets aria-invalid, and points aria-describedby at the message. Pass an array for more than one message.

Accept the terms before continuing

The border is there in the resting state too, so only its color changes and nothing moves when a form fails validation.

hint is the same line before anything goes wrong, at slate-600 behind an info mark. A checkbox can show both.

Applies to every campaign in this group.

Disabled

disabled fills the box slate-100 and drops the label to slate-500. A checked box that’s disabled keeps its check, in slate-400, rather than losing the state along with the control.

Interaction

On the page background, hovering anywhere in the row deepens the shadow from shadow to shadow-md. On a panel there is no shadow, so hover does nothing.

Pressing shrinks the box to 90% for the length of the press, and leaves the label where it is. The shrink is motion-safe, so it doesn’t run for someone who has asked for reduced motion.

Focus draws a blue outline around the box, two pixels wide at a two pixel offset, and only for keyboard focus. Pressing the row doesn’t ring it. A boxed checkbox draws the outline around the whole row instead, and its border steps one shade darker on hover.

Everything else is the browser’s. Tab reaches the box and Space toggles it. Boxes in a set are each their own tab stop, unlike a set of radios.

The label, the description, and the messages clear AA.

The mark is what carries the state. Black on sky-300 is 12.6:1, so a checked box reads as checked from its shape and not from its color. The fill underneath it doesn’t clear anything. Sky-300 against a white card is 1.7:1, and the sky-500 border that edges it is 2.7:1, both short of the 3:1 WCAG asks of a control’s boundary. The unchecked box has the same problem at 1.5:1, and so does the rose-300 error border at 1.9:1, which is why the message under the row carries the error rather than the color.

The disabled check runs slate-400 on slate-100 at 2.4:1. Disabled controls are exempt from the contrast rules, and it is deliberately quiet.
